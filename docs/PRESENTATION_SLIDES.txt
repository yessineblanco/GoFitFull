SLIDE 3 — PROBLEMATIQUE
------------------------
Title: The Problem GoFit Addresses

- Most gyms and fitness spaces operate without any dedicated application or digital management system.
- Coaches rely on scattered tools (WhatsApp, spreadsheets, paper) to manage clients, schedules, and payments — creating inefficiency and poor follow-up.
- Users who want to train seriously have no single platform to plan workouts, track body progress with precision, and connect with a professional coach.
- There is no integrated AI-powered body measurement tool available to everyday fitness users, forcing manual and inaccurate tracking.
- The fitness industry needs an innovative, all-in-one solution that serves users, coaches, and administrators in one connected experience.

SLIDE 5 — SOLUTION PROPOSEE AVEC VALEUR AJOUTEE
-------------------------------------------------
Title: GoFit — The Proposed Solution

- GoFit is a unified fitness platform with a cross-platform mobile app (clients and coaches) and a web admin panel (administrators).
- For users: personalized workout planner, exercise library, progress tracking with AI body measurements, coach discovery and booking.
- For coaches: client management dashboard, program delivery, session scheduling, messaging, and revenue/pack tracking.

SLIDE 6 — METHODOLOGIE DE TRAVAIL (Scrum vs. Others)
------------------------------------------------------
Title: Why Scrum? Methodology Comparison and Justification

Comparison: Scrum vs. Other Methodologies

Criteria          | Scrum               | Waterfall            | Kanban               | V-Model
-------------------|---------------------|----------------------|----------------------|---------------------
Approach           | Iterative sprints   | Linear sequential    | Continuous flow      | Sequential + testing
Flexibility        | High (backlog adapts)| Low (fixed scope)   | Medium               | Low
Client feedback    | Every 2 weeks       | End of project only  | Ongoing but informal | End of each phase
Risk management    | Early detection      | Late detection       | Moderate             | Late detection
Delivery speed     | Incremental/fast     | Single delivery      | Continuous           | Single delivery
Best suited for    | Evolving products    | Fixed requirements   | Support/maintenance  | Safety-critical

GoFit Scrum Team:

Role             | Person           | Responsibility
-----------------|------------------|--------------------------------------------------
Product Owner    | Nouar Malek      | Backlog priority, feature validation, business decisions
Scrum Master     | Yessine BLANCO   | Sprint facilitation, process tracking, blocker resolution
Developer        | Yessine BLANCO   | Design, development, testing, deployment

Why Scrum was chosen for GoFit:
- GoFit requirements evolved throughout the internship — Scrum's adaptive backlog handles changing priorities naturally.
- Delivering working increments every 2 weeks kept progress visible and validated by the supervisor (Product Owner).
- Scrum ceremonies (Planning, Daily, Review, Retro) enforced discipline without heavy documentation overhead.
- The sprint structure aligned perfectly with the academic timeline (13 sprints x 2 weeks = full internship coverage).
- As a solo developer acting also as Scrum Master, the framework provided self-discipline and structured delivery without requiring a large team.


SLIDE 7 — TECHNOLOGIES A UTILISER
-----------------------------------
Title: Technology Stack

- Mobile Development: React Native + Expo for cross-platform iOS/Android delivery, with TypeScript and StyleSheet for type safety and styling.
- Admin Web Panel: Next.js (App Router) with Tailwind CSS and shadcn/ui for a modern, responsive admin interface.
- Backend and Database: Supabase providing PostgreSQL database, authentication (GoTrue), file storage, and real-time subscriptions.
- Real-Time Communication: Supabase Realtime for live messaging and WebRTC (LiveKit) for video call capabilities between coaches and clients.
- AI and Computer Vision: MediaPipe for automated body-measurement analysis from user photos, replacing manual input with intelligent tracking.

SLIDE 10 — NON-FUNCTIONAL REQUIREMENTS
---------------------------------------
Title: Non-Functional Requirements

- NFR01 Security: Supabase Auth, secure sessions, Row Level Security on all data
- NFR02 Privacy: Users access only their own sessions, measurements, and programs
- NFR03 Performance: Fast loading on exercise library, workouts, and active sessions
- NFR04 Reliability: Error handling on workout creation and session save — no data loss
- NFR05 Maintainability: Modular code — screens, services, Zustand stores, UI components, types
- NFR06 Compatibility: Cross-platform mobile (Expo/React Native) + modern browser admin panel
- NFR07 Usability: Readable UI during training — clear navigation, loading states, error messages
- NFR08 Scalability: Architecture ready for coaches, bookings, notifications, and AI features
- NFR09 Internationalization: English and French support (i18next)
- NFR10 Traceability: Admin actions and workout data remain identifiable over time

SLIDE 12 — PHYSICAL ARCHITECTURE
---------------------------------
Title: Physical Architecture and Deployment

Three execution environments:
- Mobile Device: GoFitMobile (Expo/React Native, iOS + Android) + Expo SecureStore
- Admin Workstation: Web Browser → Admin Panel (Next.js)
- Supabase Cloud: Auth, PostgreSQL (RLS), Storage, Edge Functions

External services:
- Expo Push Service (FCM/APNs) for workout reminders
- LiveKit for video calls between coaches and clients
- Groq API for AI workout generation and coach briefings
- Cloudflare R2 (optional) for media storage

Why this architecture:
- Keeps the mobile app lightweight; centralizes sensitive data in Supabase
- Protects access through Auth + RLS; scales by adding services without redesigning the whole system

SLIDE 14 — CLASS DIAGRAM: CLIENT CORE
--------------------------------------
Title: Class Diagram — Client Core (Workouts and Progress)

Main entities:
- User → UserProfile (1:1)
- User → Workout (1:N) → WorkoutExercise (N) ← Exercise
- User → WorkoutPlan (1:N) — scheduled sessions
- User → WorkoutSession (1:N) — completed sessions with exercisesCompleted JSON
- User → ProgressMeasurement (1:N) — weight, chest, waist, hips
- User → Goal (1:N) | NotificationPreference (1:N)

Key design choice:
- Workout history is saved without duplicating exercise data unnecessarily (snapshots in WorkoutExercise).
